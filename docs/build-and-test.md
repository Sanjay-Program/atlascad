### Headless integration client

```sh
cargo build -p cad-cli
./target/debug/atlas box   --size 10,10,5 --out box.stl --header box.json
./target/debug/atlas union --a 10,10,10 --b 4,4,10 --offset 8,8,0 --out union.stl
```

Verified independently with a Python binary-STL parser: the box is 12 triangles, volume 500.0000 mm³,
0 open edges, 684 bytes; the union is 82 triangles, volume 1120.0037 mm³, 0 open edges.

The 26 adapter tests assert **analytic** volumes, not self-consistency:

| Test | Assertion |
|---|---|
| `extruded_box_has_the_exact_analytic_volume` | 10×10×5 mm box = 500 mm³ ± 1e-6 |
| `extruded_box_has_the_expected_bounding_box` | min (0,0,0), max (10,10,5) ± 1e-9 |
| `tessellation_is_valid_and_closed` | `validate()` ok, ≥12 triangles, signed volume 500 ± 1e-6 |
| `intersection_is_exactly_the_overlap` | 2×2×10 overlap = 40 mm³ ± 0.5 |
| `union_counts_the_overlap_once` | 1000 + 160 − 40 = 1120 mm³ ± 1 |
| `difference_is_refused_rather_than_returned_wrong` | returns `Unsupported`, never a wrong solid |
| `operands_survive_a_boolean` | inputs unchanged after a union |
| `release_is_idempotent_and_invalidates_the_handle` | 200→0 live, reuse is `UnknownSolid` |
| `bad_input_is_reported_as_invalid_not_as_a_kernel_crash` | degenerate profiles are `Invalid` |
| `tessellation_tolerance_is_bounded` | ≤0, NaN, below kernel minimum are `Invalid` |
| `handles_from_another_kernel_are_rejected` | cross-instance handle is `UnknownSolid` |
| `repeated_booleans_agree_in_volume` | identical runs agree to 1e-6 |
| `advertises_exactly_what_it_implements` | difference/Fillet/STEP/WASM **not** advertised |
| `an_expired_deadline_returns_timeout_and_leaves_the_kernel_usable` | an expired budget is `Timeout`, and the next call on the same instance succeeds |
| `every_budgeted_entry_point_enforces_the_deadline` | no entry point bypasses the budget |
| `a_cancelled_token_stops_the_operation_and_can_be_reset` | cancel is observed; `reset()` restores the token |
| `cancelling_a_running_operation_is_observed_and_the_instance_survives` | a mid-flight cancel is observed and the kernel stays usable |
| `the_trait_path_never_reports_cancellation` | the plain trait methods never report `Cancelled`/`Timeout`, so the trait's contract stays honest |

> **A cautionary note recorded on purpose.** The first version of these tests used
> `let Ok(x) = call() else { return }`, which makes a failed kernel call *pass the test*. It hid a
> completely broken boolean. They now return `Result<(), KernelError>` so failures propagate. If you
> add tests here, do not reintroduce the early-return pattern.

## 6. Reproducing the licence inventory

```sh
cd apps/cadcraft && cargo metadata --format-version 1 > /tmp/meta_cadcraft.json
cd apps/solidcraft && cargo metadata --format-version 1 > /tmp/meta_solidcraft.json

jq -r '.packages[] | .license // "UNKNOWN"' /tmp/meta_cadcraft.json | sort | uniq -c | sort -rn
jq -r '.packages[] | select((.license // "UNKNOWN") | test("GPL|MPL|CDDL|SSPL|UNKNOWN";"i"))
       | "\(.name) \(.version) => \(.license)"' /tmp/meta_cadcraft.json | sort -u
```

A combined notice bundle for distribution can be generated from the same data (name, version, licence,
repository) — that is roadmap item R-3 in `docs/roadmap.md`, and it is **not** done yet for the two
application workspaces.

The **root workspace** is covered by two offline commands instead of this inventory:

```sh
cargo run -q -p cad-engineering --bin atlas-eng -- licences   # 83 packages, policy-checked
cargo run -q -p cad-engineering --bin atlas-eng -- sbom --write
```

`licences` fails closed: a licence that is denied **or that the policy does not recognise** fails, and
a banned kernel is refused whatever its licence says. `sbom --write` emits a deterministic CycloneDX
1.5 SBOM to `engineering/sbom/atlascad.cdx.json`, which `./scripts/package.sh` ships.

## 7. Continuous integration

The root workspace now has one gate and one workflow:

```sh
./scripts/gate.sh          # fmt, clippy -D warnings, tests, corpus, manifests, licences, SBOM, live sim
./scripts/package.sh       # build, stage, archive, extract, checksum-check and smoke-test the bundle
```

`.github/workflows/ci.yml` runs the gate, packages and uploads the bundle and the SBOM, and a second
job runs `cargo-deny check advisories bans sources` with the policy in `deny.toml`. **The workflow has
not been executed on a runner** — it was written on a host that cannot run GitHub Actions, and the
gate it calls is the one that was run and recorded here (`engineering/quality/tests.json`,
`t-platform-workspace-20261029-gate`).

Neither application's CI was executed here. For the new crates, the gate above supersedes the earlier
four-line snippet; it also builds the kernel corpus rather than the single bench fixture, and the
corpus exits non-zero on a regression *or* an unexpected pass.

Do **not** add `cargo build --workspace` to CI on a machine like this one; it will exceed memory. The
gate builds `--all-targets`, which is what needs memory here; on a runner with ≥16 GB and ≥8 cores the
whole-workspace build is reasonable and is what the apps' own workflows do.
